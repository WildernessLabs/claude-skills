# Target profile: ESP32-S31 (Espressif, RISC-V dual-core HP + LP core)

Board: ESP32-S31 Function-Coreboard-1, chip revision v0.0. Measured 2026-11-17
with ESP-IDF v6.1, OpenOCD v0.12.0-esp32-20260703 and riscv32-esp-elf-gdb 17.1,
on a plain ESP-IDF app (project ESP32-S31-Template). Read `esp32-family.md` first.

## IDF: preview target `(measured)`

- `idf.py set-target esp32s31` **fails** in IDF 6.1 (exit 2): `esp32s31 is still
  in preview. You have to append '--preview' option after idf.py`. The project
  stays on its old target (here `esp32`, Xtensa), and every later build is for
  the wrong chip. Use `idf.py --preview set-target esp32s31`.
- Once the target is set, plain `idf.py build/flash/monitor` works without
  `--preview`. A direct CMake configure (CLion) also works; the gate is only in
  idf.py's set-target.
- IDF 6.1 idf.py uses `CMakePresets.json`: a preset named `default`, or else the
  first preset, gives it the build dir. Name the preset `default` with
  `binaryDir build` so that CLion and idf.py share one build directory.

## Connection `(measured)`

- `openocd -f board/esp32s31-builtin.cfg` over the built-in USB-Serial/JTAG
  (`/dev/cu.usbmodem101`). Two JTAG TAPs; targets `esp32s31.hp.cpu0` and
  `esp32s31.hp.cpu1` (`$_TARGETNAME_0` = cpu0). GDB server on 3333 (cpu0).
- FreeRTOS awareness left on works: `info threads` lists main, IDLE0/1, ipc0/1,
  esp_timer. CLion 2026.3 stopped correctly at an `app_main` breakpoint 3 of 3
  launches with awareness on.
- `gdb-detach` resume hook (as in `esp32p4.md`) on cpu0 → after GDB detach and
  after CLion Stop, **both** cores read `running`.
- Read core state without disturbing it:
  `openocd -f debug.cfg -c 'init; echo "S [esp32s31.hp.cpu0 curstate]"; shutdown'`
  (`init` does not halt). Note `-c "init; reset halt; ...; exit"` leaves the
  cores halted after OpenOCD exits.

## Console `(measured)`

- Default sdkconfig: primary console UART0 on GPIO 58/59 (external bridge,
  `/dev/cu.usbserial-110`); secondary console on USB-Serial/JTAG. ROM and boot
  logs appear on usbmodem too.
- Pulsing RTS on `/dev/cu.usbmodem101` (dtr=False, rts True→False) resets the chip
  into a normal boot (`rst:0x17 CHIP_USB_UART_RESET`, `SPI_FAST_FLASH_BOOT`),
  **not** download mode, unlike the C6.

## Memory map `(measured, from boot log / symbols)`

- Flash XIP text at `0x4000_0000+` (app_main `0x4000c676`, `.flash.text`);
  rodata maps at `0x4001_8020`.
- Internal RAM `0x2F00_0000`-ish (IRAM/DRAM loads at `0x2f000000`); ROM
  bootloader loads at `0x2f06xxxx`/`0x2f074xxx`; RTC RAM at `0x2E00_0000`.
- Flash offsets: bootloader `0x2000`, partition table `0x8000`, app `0x10000`.
- Board flash detected as 16 MB.

## Board peripherals `(measured)`

- WS2812 RGB LED on GPIO 60. It works with `espressif/led_strip` 3.1.0, RMT
  backend at 10 MHz, colour order GRB (the user confirmed the colour-wheel
  order by eye).

## CLion 2026.3 set-up `(measured, 2026-11-17)`

Working files are in github.com/NevynUK/ESP32-S31-Template: `CMakePresets.json`,
`debug.cfg`, `flash.sh`, `scripts/clion/{openocd,gdb}` and
`.idea/runConfigurations/{Flash,S31_Debug}.xml`. They are the P4 recipe
(`esp32p4.md`) with the S31 board cfg.

- **A preset added while the project is open starts disabled.** `load_cmake`
  returned `NO_PROFILES_ENABLED` until `enable_cmake_profiles(["default"])` was
  called. Delete any old workspace profile that uses the same build directory
  first.
- **CLion generates one "CMake Application" run configuration per CMake target**
  (185 for a bare IDF app) and selected `bootloader` as the active one, which
  can't run on the host. They are stored only in `.idea/workspace.xml`
  (`type="CMakeRunConfiguration"`). Removing them with CLion closed (keep the
  `default="true"` template) survived a reopen and a CMake reload.
- **The before-launch step works:** the Embedded GDB Server config with a
  `RunConfigurationTask` → Shell Script `Flash` ran `flash.sh` before OpenOCD
  started. Proven with a marker file written by `flash.sh` (`build/.last_flash`)
  that matched the `Debugger started` time in idea.log.
  **Retraction:** the timestamp of `build/*_flashed.bin` is no evidence either
  way. esptool's `--diff-with` path does not rewrite it when no sectors change,
  so a real flash looked as if it had been skipped.
- CLion's clangd reports `Unknown argument -fno-shrink-wrap` and an unsupported
  `-march=rv32imafc_..._xesploop_xespv` on every IDF file. These come from the
  code analyser only and do not affect the build.
- `idf.py` 6.1 uses the `default` preset's `binaryDir` (`build/`), so `idf.py`
  and CLion share one build. Running each in turn (IDF CMake 4.0 vs CLion's
  bundled CMake) caused no problems.
